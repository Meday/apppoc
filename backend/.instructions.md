# Backend — Symfony / API Platform

## Stack

- PHP 8.4, Symfony 8.0, API Platform 4.3, Doctrine ORM 3
- Serveur : FrankenPHP (embarqué comme sidecar Tauri en prod)
- Base de données : SQLite (`pdo_sqlite`)

## Structure

- `src/Entity/` : entités Doctrine, décorées avec `#[ApiResource()]`
- `src/Repository/` : repositories Doctrine
- `src/Controller/` : controllers Symfony (si nécessaire, préférer les opérations API Platform)
- `config/packages/` : configuration Symfony (YAML)
- `migrations/` : migrations Doctrine
- `public/index.php` : point d'entrée FrankenPHP

## Conventions de code

- **PHP 8.4** : utiliser les features modernes (readonly properties, enums, match, named arguments, property hooks)
- **Mapping Doctrine** : toujours par **attributs PHP 8** (`#[ORM\Column]`, `#[ORM\Entity]`), jamais par annotations ou XML
- **API Platform** : exposer les entités via `#[ApiResource()]` directement sur la classe Entity. Utiliser les attributs API Platform pour configurer les opérations, filtres, et serialization groups
- **Services** : autowiring activé, autoconfigure activé. Déclarer les services dans `config/services.yaml` uniquement si une configuration explicite est nécessaire
- **Pas de controlleurs REST manuels** : privilégier les opérations API Platform (state providers/processors) plutôt que des controllers custom
- **Typage strict** : toujours typer les paramètres, retours et propriétés
- **Nommage** : PascalCase pour les classes, camelCase pour les méthodes et propriétés

## Commandes utiles

- `php backend/bin/console doctrine:schema:create` — créer le schema
- `php backend/bin/console doctrine:migrations:migrate` — appliquer les migrations
- `php backend/bin/console doctrine:migrations:diff` — générer une migration
- `php backend/bin/console cache:clear` — vider le cache
