# Desktop — Tauri v2 / Rust

## Stack

- Tauri v2, Rust edition 2021
- Plugins : `tauri-plugin-shell` (sidecar FrankenPHP), `tauri-plugin-opener`
- Serde pour la sérialisation JSON

## Architecture

- Le backend Symfony est lancé comme **sidecar** via `tauri-plugin-shell` (binaire FrankenPHP dans `binaries/`)
- En production, le backend (config, public, src, vendor, migrations, templates) est bundlé dans les ressources Tauri (`bundle.resources` dans `tauri.conf.json`)
- En dev, FrankenPHP utilise le chemin relatif `backend/public` comme fallback
- Le sidecar est tué proprement à la fermeture de l'app (`RunEvent::Exit`)

## Structure

- `src/lib.rs` : logique principale (setup Tauri, lancement sidecar, gestion état)
- `src/main.rs` : point d'entrée (appelle `lib::run()`)
- `tauri.conf.json` : configuration Tauri (fenêtre, build, bundle, sidecar)
- `capabilities/default.json` : permissions (core, opener, shell:spawn/stdin)
- `binaries/` : binaire FrankenPHP pour le sidecar

## Conventions de code

- **Rust idiomatique** : utiliser `Result`, `Option`, pattern matching, pas de `unwrap()` en production (sauf état géré par Tauri)
- **État applicatif** : utiliser `app.manage()` avec des `Mutex` pour le state partagé (ex: `SidecarState`)
- **Commandes Tauri** : décorées avec `#[tauri::command]`, enregistrées via `.invoke_handler(tauri::generate_handler![...])`
- **Gestion d'erreurs sidecar** : le sidecar peut échouer silencieusement en dev (pas de binaire présent), loguer avec `eprintln!` sans crasher
- **Configuration** : modifier `tauri.conf.json` pour les fenêtres, permissions, et ressources bundlées. Modifier `capabilities/default.json` pour les permissions granulaires

## Commandes utiles

- `pnpm tauri dev` — lance Tauri en mode dev (compile Rust + Vite)
- `pnpm tauri build` — build le binaire final
- `cargo check` — vérification Rust sans build complet
