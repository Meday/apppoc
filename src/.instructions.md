# Frontend — SvelteKit / TypeScript

## Stack

- SvelteKit 2, Svelte 5, TypeScript (strict), Vite 6
- Adapter : `adapter-static` (SPA mode, fallback `index.html`)
- SSR désactivé (`export const ssr = false` dans `+layout.ts`)
- Package manager : pnpm

## Structure

- `src/routes/` : pages SvelteKit (routing basé sur le filesystem)
- `src/routes/+layout.ts` : layout racine (désactive SSR)
- `src/app.html` : template HTML racine

## Conventions de code

- **Svelte 5 runes** : utiliser `$state`, `$derived`, `$effect`, `$props`, `$bindable`. Ne jamais utiliser la syntaxe Svelte 4 (`let` réactif, `$:`, `export let`, stores `$store`)
- **TypeScript strict** : toujours typer les variables, paramètres et retours. Utiliser des `interface` pour les types de données API
- **Communication API** : utiliser `fetch()` natif vers `http://127.0.0.1:8080/api/`. Header `Accept: application/json` pour recevoir du JSON simple (pas JSON-LD)
- **Pas de store global** : préférer les runes Svelte 5 pour la réactivité locale. Si un état partagé est nécessaire, utiliser un module `.svelte.ts` avec `$state` exporté
- **Nommage des fichiers** : conventions SvelteKit (`+page.svelte`, `+layout.svelte`, `+page.ts`, etc.)
- **Styles** : styles scoped dans les composants Svelte (balise `<style>`)
- **Event handlers** : utiliser la syntaxe Svelte 5 (`onclick`, `onsubmit`) et non la syntaxe Svelte 4 (`on:click`, `on:submit`)

## Commandes utiles

- `pnpm dev` — serveur Vite dev (port 1420)
- `pnpm build` — build statique
- `pnpm check` — vérification TypeScript + Svelte
